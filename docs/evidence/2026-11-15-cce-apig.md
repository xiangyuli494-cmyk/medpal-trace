## 4. 两处真缺陷（本轮最重要的产出）

### 4.1 镜像缺 psycopg —— 一碰 GaussDB 必崩

```text
$ kubectl exec … -- python -c "import psycopg"
ModuleNotFoundError: No module named 'psycopg'
```

根因：`Dockerfile:22` 只有 `pip install -e .`，而 `pyproject.toml:21` 把 `psycopg[binary]` 放在
`optional-dependencies.huawei` 里；`Dockerfile:19-21` 的注释自己写了「B10 接云时换 `-e ".[huawei]"`」，但没落地。

修复：显式装 `psycopg[binary]`（有 manylinux 轮子，slim 镜像不需要 gcc）。不直接改用 `.[huawei]`，因为同组的
`esdk-obs-python` 依赖 `crcmod`（只有 sdist、无 Linux wheel），一起装会构建失败。

### 4.2 `autocommit=True` 与 SAVEPOINT 冲突 —— 写 trace 500

```text
psycopg.errors.NoActiveSqlTransaction: SAVEPOINT can only be used in transaction blocks
```

`providers/huawei/gaussdb.py` 原第 117 行 `conn.autocommit = True`，而 `trace/writer.py` 的 `_insert_trace`
用 `SAVEPOINT` 兜 trace_id 撞号（#69 的修复）。psycopg 在 autocommit 下没有事务块，SAVEPOINT 直接报错，
`POST /v1/ask` 落库阶段 500。sqlite 侧因为 `isolation_level` 默认有隐式事务，同一段代码不报错。

**这条 CI 抓不到**：B1 的九步自检只覆盖读写与查询对照，不覆盖「撞号重试」分支。修复为去掉 autocommit，
写路径本就在 `store` / `version` / `writer` 里显式 `commit()`，与 sqlite 同语义。
