# 答辩 20 问（2026-11-24，t1 试讲稿）

> 每答先给结论，再指证据；数字、云端状态以最终验收为准。本稿供三人对练，不代表材料已正式提交。

## 1. 作品解决什么问题？
回答能否核查来源、推理步骤和引用缺口。使用合成演示语料，将科室、检查及已收录药品名称与来源挂接，不用于临床诊断。证据：[方案书](../solution/方案书.md)。

## 2. 为什么不直接用大模型问答？
单段自然语言不能保证引用真实存在。本项目先从本体路径形成结构化结论，再让模型补充 narrative，保存可回读的 trace。证据：[pipeline](../../apps/api/app/pipeline.py)。

## 3. 六步链具体是什么？
retrieve、entity_extract、std_align、kg_query、conflict_check、conclude。图查询取已入库的路径，冲突检查保留矛盾信息。证据：[pipeline](../../apps/api/app/pipeline.py)。

## 4. 什么是原文锚点？
资产中的可定位文本单元，以 asset_id 和 anchor_id 标识；引用解析时核对它是否真实存在。证据：[资产解析器](../../packages/core/medpal_core/assets/parsers.py)。

## 5. 溯源完整率如何计算？
按引用是否可解析计算，1 减未解析引用数除以总引用数。它衡量引用可核对程度，不是医学正确率。证据：[trace writer](../../packages/core/medpal_core/trace/writer.py)。

## 6. 零引用为什么可能是 1.0？
trace 层约定零引用为 1.0 并标记 refusal；eval 将零证据样本计 0.0，纳入全部样本平均并统计 zero_evidence。前端拒答展示不应解释为高正确率。证据：[评测脚本](../../eval/run_eval.py)。

## 7. 如何证明 0% 是服务端算的？
用资产存在、锚点不存在的故障注入 trace，再从服务端回读完整率和 unresolved；不能在前端改数字。证据：[验收工具](../../tools/web_accept.py)。

## 8. 本体矛盾时怎样处理？
登记冲突的三元组和出处，交人判断；当前不做自动医学裁决。证据：[本体存储与查询](../../packages/core/medpal_core/ontology/store.py)。

## 9. Schema 为什么冻结？
固定可回读数据的结构，防止字段漂移。trace 顶层有 8 个必填字段，步骤必填 i/op/evidence，其余字段按 schema 约束。证据：[冻结 schema](../../packages/core/medpal_core/contracts/trace/schema.json)。

## 10. 报告地址为什么不放进 trace body？
冻结 schema 禁止额外顶层字段；回读 trace 时用响应头，正文通过独立报告端点读取。证据：[HTTP 路由](../../apps/api/app/main.py)。

## 11. 云服务真的在线吗？
11/24 本地 SQLite 应用调用真实 MaaS 并将报告上传真实 OBS，问答、报告和 trace 回读均通过，下载与本地文件逐字节一致，测试对象已删除。新镜像已推 SWR；CCE/RDS/APIG 整体部署尚未恢复，误建的失败空 RDS 已删除并核对无备份。模型 10 次短请求 P95 16.313s，未达 8s 门槛。证据：[本轮云端记录](../evidence/2026-11-23-cloud-acceptance.md)。

## 12. /v1/cloud 的 ready 能证明什么？
只证明配置字段满足条件，没有逐项访问远端验证连通性或读写。真正验收需业务请求、同一 trace 回读和对象内容核对。证据：[云配置](../../packages/core/medpal_core/providers/huawei/config.py)。

## 13. GaussDB 和 RDS 是否已互相验证？
没有。当前历史真机验证对象是 RDS PostgreSQL，适配器名称 gaussdb 不代表 GaussDB 产品已通过。具体版本需要另验 DDL、upsert、事务和查询。证据：[关系库适配器](../../packages/core/medpal_core/providers/huawei/gaussdb.py)。

## 14. 数据库临时故障是否会重启容器？
主分支当前行为与待合 #96 必须区分。#96 将存活探针改为无数据库依赖的 /livez，就绪仍用 /health；批准合并前不能算主分支已具备。证据：[PR #96](https://github.com/xiangyuli494-cmyk/medpal-trace/pull/96)。

## 15. KooSearch 接好了没有？
适配与回归已合入，没有真实实例，非零锚点召回及真实云端消融未验。显式选择未配置 KooSearch 时空召回，默认检索是 BM25。证据：[消融与限制](../../eval/ablation.md)。

## 16. 准确率 0.967 代表什么？
60 条演示问题中科室判定的本次读数；数据由 6 条手写和 54 条合成组成，不能推论临床有效性、其他领域泛化或云端并发能力。证据：[评测集](../../eval/dataset/v2.jsonl)。

## 17. 模型断网还会返回吗？
#93 用真实 POST /v1/ask 验证模型失败时 HTTP 返回、llm_error、空 narrative 和 trace 回读；环境隔离回归也已合入。不能将该结果扩展为任意数据库或网关故障都不影响请求。证据：[PR #93](https://github.com/xiangyuli494-cmyk/medpal-trace/pull/93)。

## 18. 为什么说底座可替换？
core 不依赖 apps，厂商 SDK 限在 providers，行业词通过词表注入。现有边界检查和 PG/SQLite 对照提供局部证据，新领域仍需更换数据并重新评测。证据：[边界检查器](../../tools/check_boundaries.py)。

## 19. 三人如何协作和避免自己批准自己？
按 lane 分工，PR 交由另一人独立审核；t1 自己的 PR 由 t2/t3 批准，满足 CI 后合并。问题要复现、返修、再审；#96 即使曾批准，发现回归后也暂停合并。证据：[协作规范](../06-协作与分支规范.md)。

## 20. 目前还差什么才能提交？
C10 冻结与 tag、云端剩余验收、3/5 分钟和离线成片、PPT、干净环境复现与最终回执。PDF 是提交候选，不能把文件已生成写成已报名提交。证据：[任务看板](../05-任务看板.md)。
